# 写作规则库格式说明

> 规则库是「拆完就能拿去写」的沉淀层，不是读书笔记。
> 一条规则 = 一个可执行的动作 + 一个具体出处 + 一组正反例。
> 位置：`skills/novel-study/data/rules/{维度}.md`；`plan.py --sync` 同步到 `06-素材/写作规则库/`。

## 1. 按维度分文件

| 文件 | 管什么 | 典型规则 |
| --- | --- | --- |
| `开篇.md` | 前 3 章怎么留人 | 第一句给冲突、开篇信息差、主角出场即困境 |
| `节奏.md` | 爽点、铺垫、爆发、篇幅 | 小爽点间隔、反应层占比、平淡段撑法 |
| `人物.md` | 出场、动机、关系、成长 | 配角功能化、反派升级、关系绑定 |
| `对话.md` | 对话的推动力与节奏 | 对话藏信息、短句互怼、打断的使用 |
| `章末钩子.md` | 章末与追读 | 每章必留钩、钩子递进、下章开头接钩 |
| `语言.md` | 句子、描写、去 AI 味 | 长短句交替、生活化喻体、删套话 |
| `结构.md` | 卷、单元、循环 | 卷目标、单元循环、卷末大高潮 |

一条规则只进一个文件；跨维度就拆成两条，用「关联」互相指路。

## 2. 每条规则的格式

### R-开篇-001 第一句给出「谁 + 正在失去什么」

- 为什么：读者对「正在发生的事」有耐心，对「背景介绍」没有；第一句建立损失，才有第三句的追读。
- 出处：《示例书》第 1 章
- 正例：「我把最后一张一百块压在桌上，跟老板说再赊一包烟。」（《示例书》第 1 章，摘原文不超过 3 句，不改写）
- 反例：「三月的风带着凉意，吹过这座古老的城市。」（先写天气再交代主角；错在信息出现顺序，读者三句内没拿到「谁出事了」）
- 适用题材：都市 / 悬疑 / 无限流等快节奏开篇
- 适用条件：主角第一章就得面对具体麻烦；慢热文可延后到第 2 章
- 关联：R-开篇-004
- 状态：可用

字段说明：

- **标题**：`R-{维度}-{三位序号}` + 一句话规则，动词开头、可执行
- **为什么**：一句话讲机理，不写「很重要」
- **出处**：具体到章，多章写「第 3、7 章」；书名用《》
- **正例**：原文摘句，最多 3 句，必须标出处；不改写、不概括
- **反例**：对照改写或经典错误写法，必须说明错在哪一步
- **适用题材**：写具体题材，不写「所有」；确属通用就写「通用，除……」
- **适用条件**（可选）：什么时候会失效
- **关联**（可选）：`R-维度-序号`
- **状态**：可用 / 待验证 / 已淘汰

## 3. 编号与文件头

- 编号 `R-{维度}-{001}`，如 `R-章末钩子-003`；同一文件内递增，不重用
- 淘汰的规则保留原编号，只改状态
- 每个文件顶部维护一行索引，便于 `plan.py` 和作者快速扫：

> 维度：章末钩子 · 规则数：12 · 最后更新：2026-10-20

## 4. 入库标准（缺一条就退回）

1. 出处具体到章，且该章在本机缓存里查得到（`.cache/novel-study/books/{key}/chapters/`）
2. 正例是原文摘句，不是概括
3. 反例能指出「错在哪一步」，不是只说「不好」
4. 一条规则只讲一个动作，不打包三个技巧
5. 适用题材写具体；写「通用」必须补一句例外

## 5. 维护

- 新规则先写进 `data/rules/`，不要直接改 `06-素材/写作规则库/`
- 被证伪的规则改 `- 状态：已淘汰`，补一行 `- 淘汰原因：`，不删历史
- 同一技法在多本书重复出现时合并成一条，出处全列，用顿号分隔
- 长期没被任何笔记或规则引用的，标 `待验证`，下次拆文时优先复核
- 规则库只增不删；合并时保留旧编号并注明「已并入 R-xxx」

## 6. 与笔记的分工

| | 笔记 `data/notes/{书名}.md` | 规则 `data/rules/{维度}.md` |
| --- | --- | --- |
| 粒度 | 一本书的整体拆解 | 一条可执行技法 |
| 读者 | 拆解者自己 | 写作时直接翻 |
| 出处 | 章节范围 | 具体到章 |
| 更新 | 拆完即定稿 | 长期增量维护 |
| 模板 | `references/note-template.md` | 本文件 |
