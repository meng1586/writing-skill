# 单元阅读执行手册（给读书子代理）

目标：一次处理明确指定的一本书和一个单元，只返回简短结果；正文不塞入主会话。

## 前置与选书

在当前克隆仓库根目录执行。所有路径相对此目录；不要切到原作者的工作区或父仓库。主会话须传入已有书目的 `book_key`，不靠上一篇笔记猜选书。

```bash
python3 skills/novel-study/scripts/plan.py --book-key {book_key} --chapters {本次章数} --json
```

- `selected_book.key` 必须与指定 `book_key` 相同。计划中的 `today` 项携带 `source`、`book_id`、`from`、`to`、`local_dir`；正文、笔记和进度都沿用这一个身份。
- 章数按当前任务和自然边界决定，未指定时可从 10 章起；不超过 `config.json` 的单次上限。自然边界未读全，只下片段范围内的结论。
- `today` 为空时，查看所选书的状态与已读/总章数；已完成就返回“该书已读完”，其他情况报告原因，不另换一本。
- 进度由 `shelf.json` 中该书的 `chapters_done` 决定。历史 `data/state/reading-progress.json` 是旧单书记录，不用它推算新书范围，不自动覆盖、迁移或清零。

## 读前情与正文

读 `skills/novel-study/data/notes/{书名}/前情提要.md`（若存在），不要重读整本旧正文。必要语境不足时，只补当前判断依赖的前后文，说明覆盖范围。

按本次计划的 `local_dir` 取 `chapters/0001.txt` 等四位数字文件。若文件缺失或明显不完整，按计划返回的两个独立字段补抓：

```bash
python3 skills/novel-study/scripts/fetch.py book --source {source} --book-id {book_id} --from {A} --to {B} --json
```

`book_key` 是 `source-book_id`，不能整体传给 `--book-id`。使用自定义缓存时明确传 `--outdir`，并核对返回 `key`、`outdir` 与所选书及缓存目录一致。补抓仍失败就标明缺章；不得编造，也不得把未读章节记为读完。

## 写新笔记

文件名：`skills/novel-study/data/notes/{书名}/第{A:03d}-{B:03d}章.md`。如果目标文件已完成，先核对是否重复派发，不覆盖它。

按[阅读笔记模板](note-template.md)记录情节梗概、读者层、拆解层、语言/风格指纹及写作层。摘句标章号，区分原文事实、效果解释和写作假设；没有覆盖的维度如实写未覆盖。批评有依据才记，未发现也可直说，不凑固定数量。

情绪问题先看[表达问题与条件选择](../data/rules/情绪.md)；试验卡可选。宏观问题需要完整冲突或卷间因果时看[卷纲模板](卷纲模板.md)，按自然转折记录，不每单元强填四格。新方法只用于未写单元，既有笔记和正式副本不迁移、不重写。

必要时更新当前书的前情提要（设定、人物、线索和截至章号），不要以新方法重写旧单元。摘要缺失就注明，只在当前覆盖范围内补充；不制造已读记录。

## 记录进度与同步

先核对笔记已保存、章号及引用正确。只有实际读完的连续范围才计数；有缺章不能越过缺口推进。再次核对所选书的 `chapters_done` 仍为本次计划的 `last_read_chapter`；若已变化，先排查重复派发，不再累加一次。

```bash
python3 skills/novel-study/scripts/shelf.py log --key {book_key} --chapters {实际连续读完章数} --minutes {估计分钟数} --note "读完 {A}-{B} 章"
python3 skills/novel-study/scripts/plan.py --sync
```

核对日志返回的书目和累计章数，不再另改全局单书进度。同步只发布本次新笔记及确需更新的规则；如正式笔记已存在且不同，停止并报告冲突，不覆盖旧笔记。提交或推送是否执行取决于当前任务授权，不把它当作阅读必做步骤。

## 返回与停止

成功只返回一行：

```
已读完 {A}-{B} 章｜笔记 {文件名}｜一句话：{本单元观察}
```

缺章、身份不符、文件冲突或进度变化时说明具体未完成范围，不返回“已读完”。不贴正文或长段笔记，不在读书任务中改脚本、模板或启动调度。
