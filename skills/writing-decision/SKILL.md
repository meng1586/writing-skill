# writing-decision：写作决策树

> **不是操作手册，是 if-then。**
> novel-study 管「读到了什么」，这个技能管「写这一场该用哪一手、为什么、会怎么崩」。

写正文时最容易发生的事：笔记读过、规则记过，真到落笔还是凭手感。
这个技能把「技法」拆成一条条**可查的决策**：

```
触发条件（题材 / 场景 / 章节位置）
  → 该用的手法（照着写的动作）
  → 为什么管用（机理）
  → 参考案例（书名 / 章号 / 原句）
  → 风险 / 崩法（写坏了长什么样）
```

## 触发词

- `/writing-decision`、`/决策`、`决策`、`查决策`、`写作决策树`、`这一场戏用什么手法`
- 「写这章用什么手法」「这一场戏怎么写」「这个场景怎么处理」
- 「主角第一次杀人怎么写」「开篇怎么留人」「章末没钩子」「对话太干」「反派不够压迫」
- 写完一章觉得「顺但不对」，想找可对照的写法

## 命令

```bash
SKILL_DIR="skills/writing-decision"

# 这一场怎么写（最常用）
python3 "$SKILL_DIR/scripts/decide.py" --tags 玄幻 --scene "主角第一次杀人"

# 章节位置也一起限定
python3 "$SKILL_DIR/scripts/decide.py" --tags 玄幻 --scene "主角第一次杀人" --position 章末

# 只看某个维度
python3 "$SKILL_DIR/scripts/decide.py" --list --dimension 对话
python3 "$SKILL_DIR/scripts/decide.py" --scene "章末没钩子" --dimension 章末钩子

# 全部决策 / 机器可读
python3 "$SKILL_DIR/scripts/decide.py" --list
python3 "$SKILL_DIR/scripts/decide.py" --tags 玄幻 --scene "反派登场" --json

# 换数据文件（调试/实验用）
python3 "$SKILL_DIR/scripts/decide.py" --list --data /path/to/decisions.json
```

| 参数 | 作用 | 默认 |
|---|---|---|
| `--tags` | 题材，逗号/顿号分隔，如 `玄幻,悬疑` | 空（不限） |
| `--scene` | 场景/情境，自由文本 | 空 |
| `--position` | 章节位置：开篇 / 中段 / 章末 / 卷末 | 空（会从 `--scene` 推断） |
| `--dimension` | 只看一个维度 | 空（全部） |
| `--limit` | 返回条数 | 4（建议 3–5） |
| `--list` | 列出全部决策 | — |
| `--json` | 输出 JSON（可与 `--list` 组合） | — |

**只依赖标准库**，不用装包。数据在 `data/decisions.json`。

## 输出长什么样

真实输出（裁剪，`--tags 玄幻 --scene "主角第一次杀人"`）：

```text
写作决策 · 玄幻 · 「主角第一次杀人」
==============================================================
共 4 条｜场景直击 4 条 · 补位 0 条
先看第 1 条：它给这场戏定调；落笔顺序看最后一节「这一场怎么串」。

1) D-014 [人物] 第一次杀人，写「身体的背叛」，不写心理独白（推演规则，待写作验证）
   匹配：场景：「第一次杀人」、「第一次杀人之后」、「杀人」｜题材：通用
   什么时候用：主角第一次亲手杀人，或第一次近距离看着一个人死。
   照着写：
     - 动手前 3 行内给一个不听话的身体细节：握刀的手在抖、牙关咬不住、听见自己的心跳。
     - 刀落之后先不写他想什么，写他做了一件多余的小事：在衣服上擦手、把刀摆正、去捡掉在地上的东西。
     - 让一个旁人看见这个动作，问一句别的（「你手怎么了」），主角答「没事」。
     - 生理反应一章最多两处；第二次要和第一次不一样（不抖了，或者抖得更厉害），那就是人物变化的刻度。
   为什么管用：读者不信「他很痛苦」，读者信「他的手在抖」。第一次杀人的重量在动作的失控，不在形容词；写身体，读者会替他把情绪补完。
   参考：《十日终焉》第1章（反例） —— 杀完人只写「众人惊恐万分，谁也不敢说话」——恐惧停在生理层，没有落到具体的人身上。
         本条由规则库 R-开篇-002 的反例和笔记的「身体动词」推演，尚未在正文里直接验证，状态标 derived。
   崩法：生理反应写太多会变成医学报告，一章两处封顶；只写抖，不写他之后怎么处理尸体/关系，会显得是为了惨而惨；第二次杀人必须有变化，否则人物在原地踏步。

...

——— 这一场怎么串 ———
[第一次杀人（完整一场）] 命中 4/4
顺序：D-014 → D-003 → D-015 → D-021
先写身体的背叛，再用一句台词把「为什么必须死」升级成制度，然后用这桩共同的罪把队伍绑住，动作段落用身体动词收。顺序别反：先让读者不适，再让读者懂规则。

下一步：把命中的条目贴进这一章的细纲/场景卡，按顺序落笔；写完回看「崩法」逐条对照。
```

四块怎么读：

1. **匹配行**：告诉你为什么它被翻出来（场景直击 / 题材 / 位置）。
2. **照着写**：这是动作，不是形容词；能直接进细纲。
3. **为什么 + 参考**：为什么管用，以及哪本书哪一章验证过。案例只引真读过的书。
4. **崩法**：写坏了长什么样。写完对照，比写完再改省事。
5. **这一场怎么串**：多条决策的落笔顺序（来自 `combos`），不是简单罗列。

`--json` 输出 `query / count / direct / fallback / matches / combo`，`matches` 里保留完整决策字段和 `score`、`matched`。

## 怎么加第 25 条

数据文件：`data/decisions.json`。一条决策的字段：

```json
{
  "id": "D-025",
  "dimension": "对话",
  "title": "一句话，动词开头，能执行",
  "trigger": {
    "genres": ["玄幻", "仙侠"],
    "exclude_genres": ["甜宠"],
    "scenes": ["对话", "审问"],
    "positions": ["任意"],
    "when": "一句话说清什么情况下用"
  },
  "move": ["第一条动作", "第二条动作"],
  "why": "为什么管用，讲机理，不写「很重要」",
  "case": {
    "book": "《书名》",
    "chapters": "第3章",
    "quote": "原文摘句，最多三句",
    "quote_type": "原文",
    "note": "这条案例好在哪"
  },
  "risk": ["写坏了长什么样", "什么时候不适用"],
  "related": ["D-001"],
  "status": "verified"
}
```

硬规则：

1. **`scenes` 第一个是主场景**，匹配权重最高；换场景词时先想清楚这条最该在什么场景被翻出来。
2. **场景词要在 `scene_aliases` 里有同义词**，否则用户说「开杀」「见血」匹配不到。新增概念时两处一起改。
3. **`case` 必须具体到章**；`quote_type` 用 `原文` / `笔记转述` / `反例`，不许把转述标成原文。
4. **`status`**：`verified`（有原文出处）/ `derived`（推演，待写作验证）/ `retired`（淘汰但保留编号）。`derived` 会在输出里标出来。
5. 一条只讲一个动作，不打包三个技巧；`related` 指路，不合并。
6. 加完至少跑一次 `--list` 和一个真实场景查询，再写进「已验证记录」。

`scene_aliases` 的结构是「场景概念 → 同义词」，例如：

```json
"第一次杀人": ["首次杀人", "第一次动手", "第一次下杀手", "杀第一个人", "开杀", "第一次见血"]
```

| `decide.py --tags 甜宠 --scene "男女主第一次接吻"` | 0 条，明确提示「不硬凑」，不返回通用噪音 |
| `python3 -m py_compile scripts/decide.py` | 通过 |

已知限制：

- 场景匹配是**关键词 + 同义词**，不是语义模型。说法太偏（比如「捅破窗户纸」）会漏；可以往 `scene_aliases` 补词。
- 只给题材、不给场景时，按维度轮转取样，不保证和当前章节位置相关；要精确就补 `--scene`。
- `derived` 目前 1 条（D-014 第一次杀人的身体反应），是推演规则，第一次照着写之后要回来补案例或改状态。

## 边界

- **不代写正文**，只给判断和动作；句子还是作者写。
- **不编案例**。没拆过的书不凭印象引用；转述标转述，反例标反例。
- **不改 novel-study 的文件**。规则/笔记更新后，手动同步成决策（以后可以写 `sync.py`）。
- **宁可返回空，不硬凑**。通用技巧套到不合适的场景，比没有建议更糟。

## 与 novel-study 的分工

| | novel-study | writing-decision |
|---|---|---|
| 回答 | 这本书怎么写的 | 我这一场该怎么写 |
| 产物 | 笔记、规则、出处 | if-then 决策、查询 CLI |
| 粒度 | 一本书 / 一条技法 | 一个场景 / 一个动作 |
| 用法 | 读的时候沉淀 | 写的时候查 |
