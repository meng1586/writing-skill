# Write

让作者的念头成为可以读的故事。先明确本次要交付什么，再把必要的规划、写作和修改连起来；方法帮助判断，不把小说变成填表。

## 单一入口

1. 读取作者本次要求和相关现稿，沿用已定人物、关系、设定、结局、文风和不可改内容。已有答案不重问，不另起一套工程。
2. 判断起点与终点：构思、大纲、剧情方案、起草、审读或修改。已有正文时从实际进度接入；只要求大纲就停在大纲。关键剧情先提出可比较的方案，讨论选定后再写正文；要求完整故事也不等于已经选定关键方案。已选内容与常规实施不重复请求批准。
3. 按作品的叙事范围与作者意图分流：围绕一次主要变化收束，读 [短篇](references/short.md)；需要跨阶段发展与持续兑现，读 [长篇](references/long.md)。字数用于控制规模，不凭固定字数机械分类。类型不明时先给出判断，只有分歧会实质改变作品才追问。
4. 进入正文前，结合主题想探索的问题、读者体验、叙述者与人物处境，确定或沿用适合的文风，具体读 [起草与接续](references/drafting.md)；已有文风与续写不因重新判断主题而擅自改换。审读或修改前读 [审读与修改](references/editorial.md)。每次只读所需分支，不把全部参考库塞进上下文。
5. 设计关键剧情时先读 [场景卡与方案比较](references/methods.md)，结合相关卡片提出少量实质不同的方案、比较取舍并给出推荐，停在方案交付，等待作者选择、组合或另提方向；推荐不算已选。写中遇到困难也可回到这里。没有匹配卡片时依据人物与故事目标提出方案，不硬套卡。需要复盘或从阅读中学习时，使用 [学习回路](references/learning.md)。

从同一份作品材料连续推进；不跳转到其他 skill，不要求新建代理或会话。内部的“作者、读者、编辑”是观察角度，可以在同一对话依次完成——这是内部审读，不等于独立审读：主笔与审读者共享上下文时，读到的只是复读，不能称首次盲读。作者要求独立审读时，冷读与编辑第一轮应使用不继承主笔历史的新上下文，只给正文、版本范围与中性指令；做不到时如实说明该项未完成，可提供内部审读但不能冒充。输入边界、两轮顺序与降级规则见 [审读与修改](references/editorial.md)。

## 全流程与资源归属

完整创作依次连接：定方向 → 长短篇规划 → 关键剧情方案比较与选择 → 连续成稿 → 文学审读与一份修改清单 → 成组修订和相关复验 → 交付；学习沉淀按需进行。用户只要求某一阶段时从那里接入，完成该范围即可。

正文审读、表达调整、所谓“去 AI 味”和设定连续性判断均在 write 内完成。遇到具体问题就调整具体文字，不另开一套写作或总审入口。封面、导入、投稿格式和发布属于另行明确请求的交付任务，不在创作中自动触发。

本包 `data/` 是默认通用方法来源；私人阅读材料、案例、验证记录留在各自项目，按需只读参考，不要求每篇先研读。旧系统的资料和脚本可以保留，创作时不启动其旧编排流程。需要核对多个资料版本、接入项目机器检查或衔接其他工作区时，读 [资源与检查边界](references/resources.md)。本包独立写作不依赖这些外部材料或工具。

## 各阶段交付与退出

| 阶段 | 默认交付 | 何时继续 |
|---|---|---|
| 构思 | 保留原始吸引力的故事方向；只列影响主选择的待定问题 | 人物、主要变化与叙述方向足够确定 |
| 短篇大纲 | 简短梗概、人物欲望与关系、自然场景顺序、结局或有意开放处 | 因果可连接，下一场可以落笔 |
| 长篇大纲 | 全书方向、当前卷推进、所需近章细纲；远期保留粗线 | 当前交付范围足够写，不必先编完整本章表 |
| 关键剧情方案 | 相关场景卡、不同事件或信息安排、优势与代价、推荐及其条件 | 作者明确选定、组合方案，或明确委托本轮代选后，才能进入相应正文 |
| 起草 | 按要求范围连续成稿，简记影响接续的新事实 | 达到本次范围，或出现必须由作者决定的根本分歧 |
| 审读 | 读后体验、文学判断、一份有优先级的修改清单 | 问题足以支持取舍，不以凑满表格为目标 |
| 修改 | 对准已选问题的修订及必要复验 | 目标已达成且无新实质问题；容许作者选择保留风险 |

作者要完整流程时按表推进；作者只要其中一步时不扩张任务。缺少时代知识、生活经验或作者偏好时，区分已知、暂定与待查；不要用虚构事实填补现实资料缺口。

选方案只针对会显著改变人物选择、因果、揭示顺序、高潮或结局的关键处。普通过渡直接写；长篇只讨论当前卷或近期拟写范围，不提前锁死全书。作者已有明确选择就沿用；若作者明确委托代选，记录范围后选定并继续。本轮要求讨论后再写时，必须等到实际选择，不能用超时、作者暂未回复或模型自评代替。

## 可选：平台适配（明确要求才用）

作者明确要求「知乎化」「番茄化」或「按平台改一版」时，读 [平台适配](references/platform-adapt.md)。默认关闭；在原剧情事实、人物、因果、结局、视角与文风约束内调整呈现，不承诺平台效果。信息顺序、标题剧透或断点若显著改变已选揭示、期待与悬念，先按 `methods.md` 比较受影响方案，取得作者选择或明确的本轮代选委托后再改；未获授权就保留原安排。原文版本不动，另出平台版并附实际改动清单。

## 文学判断先于方法配额

- 具体人物、心理、行动和对话可以充分展开；留白用于给读者理解空间，不等于抹去信息、碎片化或一律去掉心理描写。
- 关注读者在乎什么、如何理解眼前信息、因此发生什么体验变化。人物的认知、人物的情绪、读者的情绪分别判断，不规定三步必然依次出现。
- 允许安静、重复中的变化、迟疑、失败和复杂动机。反转、强钩子、报应、升高伤亡、关系改变都不能成为每场必填项。
- 具体技巧必须适合当前视角、人物状态和目标；不统一禁用某类句式、标点、解释或描写，不按固定比例分配高潮。
- 写作计划可以改变。改动若牵涉作者已定的主旨、核心关系或结局，先说明取舍；常规实施选择自行完成。

## 最少材料与准确状态

短篇默认一份规划和一份正文即可；长篇可保留全书/卷纲、当前进度与正文。能合并便合并，沿用项目现有文件，不为检查另建多份台账。

接续时指明唯一当前正文路径与版本、实际完成范围、已选和待定的关键方案、本轮修改与已核查范围；沿用已有规划或交付说明即可，不另造状态库。暂停、换对话或换工作区前留下这几项，接手者核对实际文件后继续。

计划、正文事实、未决设想明确区分。正文未写成、完整读完、内部审读完成、作者接受、真实读者反馈、对外发表是不同状态，按实际完成的范围报告。机器检查通过只证明所检查事项；模型赞同不能证明文学效果。

方法来源与吸收取舍见 [来源说明](references/sources.md)。本包只带通用方法摘要；作品、私人阅读笔记和原文材料留在各自项目。
