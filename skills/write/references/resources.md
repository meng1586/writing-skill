# 一个创作入口，分清方法、证据和检查工具

## 默认方法与私人证据

本包 `data/rules/`、`data/decisions.json`、`data/modules/` 是默认的通用方法来源，由 write 维护。它们足以独立完成本工作流；不要求访问某个私人工作区或调用旧 skill。

私人阅读笔记、原文、案例、阅读进度与反馈记录留在来源项目。来源项目的旧规则、决策或卡片可能保留独有内容，是私有证据或历史版本，不能只因条目同名、ID相同就认定为副本，更不能用摘要覆盖原件。需要核实方法来源时，由当前项目提供具体路径，按需只读查证，不全量重读资料库。

同一个ID下，摘要与原件的措辞、适用条件、验证对象可能不同。保留出处、版本及状态含义；原件的 tried、conditional 等标注不能自动迁移成当前摘要“已验证”，单次模型判断也不代表真实读者证据。旧数据存在状态冲突时说明冲突，按不确定处理，不为统一格式改写旧案例或笔记。

新通用方法的修改集中在 write。私有新案例与反馈在作者要求保留时由所属工作区追加，再提出是否值得更新通用方法；避免两边平行维护相互漂移的通用正文。只有实际内容、来源版本和用途都相同的文件才可标作资料副本；其他文件保留自己的身份。

## 旧入口怎样处理

旧入口说明可以保留为兼容导航、资料说明或工具说明，但明确把小说构思、规划、写作、审读与修改指回 write，不执行旧的多步编排。读书资料库独立存放，学习由本包 `learning.md` 组织。

旧审读、去 AI 味、总编量表和问题分诊属于编辑参考，不是机器事实检查，也不再作为另一套正文修改入口。正文的语气、节奏、解释、心理和句式由 `editorial.md` 结合具体文本判断，不一律禁用某类表达。

封面、导入、投稿格式及发布是作者另行指定的任务。只有当次明确请求才处理相应输出，不自动调用平台技能改写正文，也不把稿件完成或作者接受理解成已经授权公开发布。

## 可选项目机器检查

机器工具只辅助明确的事实、连续性、版本与交付范围检查。例如项目已有设定账、规则检查或门禁脚本，可以按实际风险使用；不要求每篇安装工具，也不默认定稿前全套必跑。

在候选稿上选择有关检查 → 核实其输出和文本证据 → 合并到同一份当前修改清单 → 由编辑区分阻断问题、可选建议和误报 → 修订后复验受影响项。版本变动不等于所有检查失效；也不能把旧PASS自动盖给新稿。工具出错、输出不完整或当前版本未核对，就如实记为未完成，不能当作通过。

运行前确认目标文件、参数和写入位置。会写报告、缓存或自动修复的命令只在所属工作区或独立临时副本执行；访问对方工作区只能读，不在那里运行可能产生写入的命令。尚未核实项目命令时先读说明和代码，不猜 `make gate` 等命令，不顺带修改凭据、配置或会话。

当前任务无需机器检查时按文学流程正常交付，说明实际审读和复验范围。当前任务明确要求某项正式检查却无法完成时，保留该项未完成状态；机器结果、内部编辑判断、作者决定与真实读者反馈分别报告。

## 分工与交接

入口维护者修改 write 的流程与通用摘要；资料和项目工具由所属工作区维护者处理。跨工作区建议通过已授权的协作渠道提出，任何一方都不代写另一方文件。双方可以有分歧，记录依据与待决处；代理间对流程的共识不能代替作者选择剧情或接受作品。

讨论整体流程时比较同一版文件，明确已同意、仍待讨论、各方待实施的内容；只收到提议或消息已发布，不能称双方已同意或两端已落地。写作接续只需当前正文版本、完成范围、已选/待定、修改与已验范围，不建立另一套重复回执。

## 工具说明（2026-10-22）

- Node 为可选依赖，无 npm 包；脚本只用标准库与同目录文件。
- 用法：`node scripts/check-ai-patterns.js --check --json --fail-on=blocking 文件.md`；`check-degeneration.js` 同。
- 退出码：`0` 无 blocking / `1` 有 blocking / `2` 运行或参数错误。运行错误必须当「未完成」，不能当 PASS。
- `check-ai-patterns.js` 依赖同目录 `style-whitelist.js`；只复制一个会断。
- 检测结果只是编辑线索：advisory 与 blocking 都要编辑按上下文核证，可误报，也可有意保留；不是自动重写依据。
- 旧 help/注释里「命中即重写」「永不合法」等措辞是生成/清理场景的强提示，不适用于本主流程；以 `references/editorial.md` 为准。
