# 审读 → 一份修改清单 → 定向复验

## 先取得真实的阅读范围

用户要求全篇评价，就读完全文；只读片段必须明确范围，不能给“全稿通过”。续评已有版本先核对哪些内容变了。长稿分段阅读可保留简短阅读位置与未决疑问，但不要让大纲或作者解释替正文补洞。

## 三种角度，在同一流程里完成

**读者首读**：只依据正文，先记录哪处想继续、迟疑、走神、感到亲近或疏离；理解在何处改变，哪些疑问是有趣的，哪些是信息不够。能无感、看不懂或不喜欢。不要先看目标情绪和审读量表再“验证成功”。模型首读仍是模型判断，不能称真实读者反馈。

本对话若已见构思、标准答案或作者目标，就如实称为正文复读，不能靠“切换角色”冒充独立盲读。需要独立首读证据时，交给未见这些材料的读者；日常内部编辑可以继续，不因此阻断交稿。

**文学编辑**：回到具体文本判断人物是否有独立性，行动和语言是否符合处境，叙述视角、详略、节奏和形式是否服务作品。先说作品成立之处，再指出最妨碍阅读的问题与保留的价值。结构完整、逻辑无错和文学感染力分别评价；不能用通过门禁替代后者。

**作者取舍**：结合原始吸引力与已定方向，选择值得改的事。角色可以不讨喜、动机可以复杂、结局可以开放；不要把审读者个人偏好当硬错。少数重点修得更好，胜过满足所有建议。

前期采用过场景卡、比较过方案，只说明有了写作选择；审读仍以实际正文为依据，不替已选方案证明成功。若改稿将改变已选关键剧情，回到 `methods.md` 比较受影响的方案并由作者选定，再改相应正文。

## 只维护一份可行动的清单

每项写清：具体位置与证据、造成的阅读问题、建议的最小改动及可能损失。分成必须处理和可选建议；必须处理须有依据，例如事实矛盾、缺失因果或违背作者明确要求，不能把“我更喜欢另一种风格”升级成阻断。

不要求每项一定改，也不以问题数量或评分高低表示质量。相互冲突的建议放在一起比较；已解决问题不因格式或版本号变化重新打开。

## 修改与复验按影响范围进行

先改已选问题，保留未授权改动的故事骨架和关系。局部措辞改完读上下文；时间、知情、物件或设定变化检查关联场景；视角、主线因果、结局或整体节奏大改才扩大到相关章节或全稿。每次说明实际复查范围。

新版本不能自动继承旧版本“全稿通过”。可以明确哪些旧判断未受改动影响、哪些已复验、哪些仍未检查；换一个文件 hash 不等于所有文学判断失效，也不强迫局部修改后再跑整本。

机器只检查可明确判定的事实、遗漏、版本和交付范围。不得用词频、句式数量、情绪分数或自动 PASS 证明作品好读。只有当前任务需要且有现成工具时才做相关检查，不为短篇新造门禁系统。

项目已有工具时，按 `resources.md` 选择有关检查，把核实后的问题并入同一清单。编辑量表与问题分诊仍是判断参考；机器输出先核证据和误报，不自动变成必须修订项。定稿前全套跑一次不能替代改动后的相关复验，局部改动也不触发一轮新的全套检查。

针对“去 AI 味”等要求，具体指出影响阅读的套话、重复、同质节奏或视角问题，再按人物与文风修改；不另调一套改稿 skill，不默认所有长句、解释、抒情或某类词语都有问题。

无未处理的阻断矛盾、主要问题已处理或被作者明确接受、保护项未被破坏时停止；不因还能提出偏好自动重开。作者接受风险时保留原问题与决定，不能改称已修好。报告内部审读、作者接受、真实读者反馈各自状态；未来若要比较写法，用中性问题和可比片段收集真实反馈，允许没有改善。
