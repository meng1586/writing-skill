# 场景卡参与构思、方案比较与复盘

本包内带规则摘要、决策摘要与场景卡。它们是候选方法，效果待试验；来源、写法与可用状态保留，不因被整合就变成已证实规则。

默认只检索本包的通用摘要，不在不同旧库之间反复查同一套方法。需要来源证据时按 `resources.md` 定位具体私有原件；同ID不同版本的案例和验证状态不能直接套到本摘要上。

## 关键剧情先比较，再起草

关键剧情是会显著改变人物选择、因果、信息揭示、高潮或结局的地方。规划到这些地方就主动查看相关场景卡，不必等到写坏或卡住。先说清这场想让读者经历什么、人物此刻想做什么、当前已知与不可改内容，再选读相关卡片。卡片提供可尝试的组织方式，不把作品改成卡片范例。

据此提出少量实质不同的方案，通常两三个足以比较；只保留有意义的分歧，不凑数量。差异可以来自行动、选择、揭示时机、谁先知情或后果；换几句台词、换物件颜色不算不同剧情。各方案沿用同一组作者已定条件，所需新增设定与铺垫明确说明，避免一个方案靠临时新增便利取得优势。

每个方案简要交代：

- 事件怎样发生，人物为何这样选，结果如何承接后文。
- 借用了场景卡的什么思路，为什么适合当前人物与目标；也允许保留不套卡的自然写法作为候选。
- 对读者理解、情绪、期待或余味可能有什么作用，需要哪些前文支持。
- 得到什么、牺牲什么，与其他关键剧情是否相容。

结合人物可信度、因果与知情条件、阅读目标、篇幅和全篇承接比较，说明推荐及推荐成立的条件。不要用卡片完成度或情绪分数裁决，也不默认含蓄、复杂或反转更多就更好。若效果差别必须写成片段才看得出，说明不确定处；只有作者要求试写比较时才先写那些片段。

把方案直接放进当前大纲或回复，等待作者选定、组合或修改。模型推荐、双方代理同意、要求最终写完整篇都不代表作者已选；不要在同一轮方案后接完整正文。作者已经明确选择，或明确委托本轮代选时，沿用其授权继续，不重复问同一选择。

短篇可把少数关键选择合成一份连贯剧情方案；长篇只处理当前卷或近章。相关选择应一起说明牵连，避免每场机械列三案，或把所有组合展开成一大棵树。普通场景按已选方向推进即可。作者选择后只保留简短的“已选 / 仍待定”信息，不新增审批系统。

## 按需要检索内部资源

规划关键剧情时说明本场目标，修改时说明当前问题，例如“读者提前知道答案，后半调查没有新进展”，再选择最少资源：

- 规则按当前问题选读：[人物](../data/rules/人物.md)、[对话](../data/rules/对话.md)、[语言](../data/rules/语言.md)、[节奏](../data/rules/节奏.md)、[结构](../data/rules/结构.md)、[情绪](../data/rules/情绪.md)、[章末钩子](../data/rules/章末钩子.md)、[开篇](../data/rules/开篇.md)，只取相关条目。
- 需要条件与动作的对应建议：运行 `scripts/decide.py`，或直接读 `../data/decisions.json`。
- 设计告别、谈判、揭示等关键场景时：读 `../data/modules/` 的对应卡片，或运行 `scripts/scene.py`，据此发展与比较候选剧情。

以下命令以本 skill 目录为工作目录，也可把脚本换成绝对路径；仅 Python 标准库，不联网、不写文件、不需要其他 skill：

```sh
python3 -B scripts/decide.py --scene '告别' --limit 2
python3 -B scripts/scene.py --type 告别
python3 -B scripts/decide.py --list --json
python3 -B scripts/scene.py --list --json
```

脚本不可用就直接读取本包数据，不安装外部工具。`scene.py` 无匹配时可能返回非零，含义是没有卡片；仍可按人物与目标提出方案，选定后正常起草。

## 候选如何变成选择

先核对当前人物状态、叙述视角、已给信息与希望解决的问题。检索顺序只表示文本相关性；并列或拼接推荐不代表应全部采用，场景卡步骤也不要求全写。

可以采用、改写或拒绝候选，并说明对当前目标或问题的作用与代价。一次通常只需最有用的一两个思路；不定配额，也不把规则 ID、情绪指标和方法解释塞进正文。弃用/退役条目不得因普通匹配重新启用。

“关切—判断—情绪变化”可帮助查明读者是否得到理解所需的信息，但不是每场的固定写法。生活细节可以建立经验与语气，不必逐个计算功能。审读时也可以用方法解释已观察到的问题，不能为了命中方法倒造问题。

新反馈如何进入库，见 `learning.md`。既有私人笔记不回写，本包摘要与私人来源独立维护。
