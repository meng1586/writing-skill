# 学习回路：可选，不占用每次开写

创作不以“先研读、先查库、先反思”为前置条件。作者要求学习一本作品、总结一段创作经验或整理读者反馈时，再进入这里。

## 从阅读提炼

在作者指定或合法可读的材料中，看具体段落如何产生一种体验：人物处境、读者已知信息、叙述安排、发生的理解变化。区分原文事实、自己的解释与待验证的机制；寻找不适用的情境和相反写法，避免把一次成功概括成普遍定律。

先输出少量条件明确的候选：遇到什么问题、可尝试什么、为什么可能有效、什么情况下不宜用。来源定位和原文留在私人阅读项目；公共方法只保留通用摘要。不要向现有笔记或方法库自动批量回填。

## 从实际写作与反馈提炼

记录原问题、做过的改动、观察到的结果及反馈身份：作者自评、模型判断、真实读者。读者问题用中性表述，如“在哪停顿”“你怎么理解这段关系”“愿不愿意继续”，不先告知目标情绪、预期答案或哪版应该更好。

需要比较时，选可比片段或匿名版本，允许偏好分裂、无差别和改后更差。单一读者只支持局部信号，不足以证明通用方法有效。脚本运行通过与反馈是否支持方法分别记录。

## 何时沉淀

只有作者要求保留新方法时，才在指定方法库或新笔记中追加；不改写旧笔记，不自动复活退役条目。描述适用条件、反例、来源与验证状态，继续保持候选，直到有足够可比的实际证据支持更强判断。

通用方法定义由 write 集中维护，私人案例和反馈由来源项目留存；按 `resources.md` 区分摘要、原件与历史版本。提出更新建议时说明对应方法及来源，不把私有全文、具体案例或读者身份复制进通用包，也不按相同ID覆盖旧证据。

同一问题能用一句提示解决，就不要增加新表格、脚本和强制流程。下次创作按问题检索，取不到合适方法仍可正常写。
