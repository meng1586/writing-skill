# scene-modules：场景摘要卡

场景卡保留提炼后的适用条件、候选结构与崩法；具体出处、完整案例和原文留在本地完整版。摘要不是范文，也不是已经通过效果验证的施工步骤。

## 按实际问题调用

| 需要 | 调用方式 |
|---|---|
| 写前缺方案 | 借一张卡比较候选转折是否适合当前人物和目标 |
| 写中卡住 | 明确缺冲突、反应还是转折，只借一条可用动作 |
| 写后有疑问 | 用边界或崩法定位具体句子，再对照完整上下文 |

没有按卡片的步骤写，不构成写坏的证据；卡片也不能替代大纲、人物和设定。

## 命令

在本包根目录执行：

```bash
python3 skills/scene-modules/scripts/query.py --list
python3 skills/scene-modules/scripts/query.py --type 告别
python3 skills/scene-modules/scripts/query.py --type 谈判 --json
python3 skills/scene-modules/scripts/query.py --search 选择
```

`--dir` 可指定另一份模块目录。查询只依赖 Python 标准库，不需要联网。

## 公开卡片格式

卡片位于 `data/modules/{类型}.md`，保留各自结构，不强行改成规则条目或决策 JSON：

```markdown
# 场景模块：类型名

> 一句话：本卡可帮助检查什么
> 别名：可检索的其他叫法
> 效果状态：待试验

## 适用条件
本场目标、人物处境和需要的前文信息。

## 可尝试的结构
按本卡需要列候选动作，不固定步数，不要求全部采用。

## 崩法与边界
什么现象值得复查；哪些条件下这张卡可能不适用。
```

必要时可加抽象解释、可选变体或独立虚构的教学情境，注明性质；不要把旧案例改名后标成原创示例。

## 维护

新卡保留稳定标识和别名。用 `--list` 检查是否读到，再用一个具体类型查询。试用时记录本场目标、借用步骤、实际变化及未解决问题；模型自查、作者自检和真人反馈分别记录。一次反馈不能推广成普遍结论。
