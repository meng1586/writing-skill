## 三种调用入口（按真实写作场景选，不要每次全查）

| 场景 | 怎么用 | 注意 |
|---|---|---|
| **写前缺方案** | 借一张卡的「结构」当候选转折，比较是否适合当前人物和本场目标 | 结构是候选，不是必填 |
| **写中卡住** | 先说明卡在哪（缺冲突/缺反应/缺转折），再只查一个动作或一条反例，局部试改 | 不要整章重写 |
| **写后有疑问** | 用「崩法」定位具体句子和可能后果；对照「自检清单」 | **没照五步写，不构成写坏的证据** |

**30 秒初筛可以，但别把它当读者情绪验证。**
卡片本身没有经过对照试验；每次调用只记：卡在哪、借了哪条、改了哪句、用了多久、是否引出新问题。

# scene-modules：场景模块库

写某类戏之前，先调一张卡片。卡片不是范文，是**施工图 + 事故清单**：
适用条件、五步结构、正例（书名+章号+原文）、崩法、变体。

素材来自 `skills/novel-study` 的真实拆书笔记（《十日终焉》114 篇单元笔记中抽读 13 篇提炼）。
**没读过的书不写进卡片**——这是本技能和"网上套路总结"的区别。

听到这类话，先跑 `--type` 取卡片，再动笔。

## 命令

```bash
cd skills/scene-modules

# 看全部模块
python3 scripts/query.py --list

# 取整张卡片
python3 scripts/query.py --type 打脸
python3 scripts/query.py --type 告别

# 按别名取（告别 = 诀别/送别/临终/散伙）
python3 scripts/query.py --type 诀别

# 全文搜关键词，返回模块 + 命中行
python3 scripts/query.py --search 倒叙

# JSON（可接脚本/其他 agent）
python3 scripts/query.py --list --json
python3 scripts/query.py --type 谈判 --json
python3 scripts/query.py --search 蒙太奇 --json

# 换一个卡片目录（做实验时）
python3 scripts/query.py --type 打脸 --dir /tmp/modules
```

只依赖 Python 3 标准库。没有网络、没有第三方包。

## 十二张卡片速查

| 类型 | 一句话 | 什么时候调 |
|---|---|---|
| 打脸 | 让对手在他最得意的规则里、当着最想看戏的人输一次 | 对手先立威、主角握着一张规则牌 |
| 反转 | 让读者自己补错一个前提，再当众收走 | 前面铺了三十章以上、读者猜错过 |
| 告别 | 把"再见"换成一个动作，把最重的话押到事后 | 有人不会再回来、要改变留下的人 |
| 绝境 | 先给三条规则，再让读者自己算出"他活不了" | 灾难/围杀需要一个可复述的规则 |
| 托孤 | 把"帮我照顾他"说成交易、命令或授权 | 托的人没退路、接的人不情愿 |
| 翻盘 | 先看见败相，再用对手自己的话翻过来 | 主角真输过、翻盘点前文出现过 |
| 谈判 | 先把筹码摆上桌，再用对方的欲望定价 | 双方互有所求、谁都杀不了谁 |
| 追逐 | 让"逃"本身变成伤害，每步都在给别人设陷阱 | 追兵有规则、必须带走人/物 |
| 揭示 | 答案交给称呼、物证、动作，不交给说明 | 答案埋了三十章以上、改变主角自我认知 |
| 爆发 | 把选择堵死，只写一个动作、一句话 | 压了三章以上、退路被当面切断 |
| 立威 | 用一次越界行为，让所有人重新报价 | 新团队/新地盘、有人当众挑衅 |
| 交易 | 先定价，再让利，最后加一条对方没想到的条款 | 双方互有所求、交易比抢夺划算 |

## 怎么用（候选流程，不是必做）

1. **定型**（可选）：这场戏要解决一件事，跑 `--list` 看看有没有对得上的卡。没有就正常写。
2. **对条件**：读卡片「适用条件」。若「别用」里中了一条，**可以**换类型——但不是命令，也可以只借其中一步。
3. **按结构写**（可选）：五步是候选，能借两步就借两步。**没照五步写，不构成写坏的证据。**
4. **对崩法自查**：写完后对照「崩法」定位具体句子，看是否真的出了那个问题。
5. **换变体**（可选）：同类型连着出现时，换一种写法，避免读者疲劳——但这是经验建议，不是硬规定。

技术细节（人名、伏笔、章节字数）以项目大纲和追踪文件为准；卡片只管"戏怎么搭"。

## 卡片格式（新增模块照这个写）

```markdown
# 场景模块：类型名

> 一句话：……
> 别名：A、B、C
> 素材来源：novel-study 笔记（第 X–Y 单元）

## 适用条件
**该用** / **别用**

## 结构（五步，动词开头）
1. ……

## 正例
- **《书名》第 N 章 · 场景名**
  > 「原文摘引，最多三句」

  为什么成立：……

## 崩法（2–3 种）
## 变体（两种换法）
## 自检
```

硬规则：
- 正例必须**真读过**（来源写在卡片头部），标书名 + 章号；原文摘引不超过 3 句。
- 结构每步动词开头，能直接照着做。
- 崩法写"最容易写崩的样子 + 改法"，不写空话。
- 变体必须是**同一模块的两种换法**，不是另外两个模块。

## 和其他技能的关系

- `novel-study`：上游。它负责读、拆、沉淀笔记；本技能只从它的笔记里提炼"可调用的场景卡"。**不要改 novel-study 的文件。**
- `story-long-write` / `story-short-write`：下游。写正文卡住时调卡片；卡片不替代大纲和追踪。
- `scene-craft`：互补。它管"一段场景怎么写细"（环境、五感、镜头），本技能管"一场戏怎么搭"（结构、正例、崩法）。同一场戏可以先用本技能搭骨架，再用 scene-craft 填画面。

---

## 维护

- 新增卡片：照上面的格式写 `data/modules/{类型}.md`，跑 `--list` 确认能读到。
- 新卡片要有**新的正例来源**（另一本书的另一章），不要拿同一段素材换皮。
- 卡片里的引文如果和原文对不上，以原文为准并修正卡片；`SOURCE.md` 记录改动。
- 验证记录写在 `SOURCE.md`，不写进卡片正文。
